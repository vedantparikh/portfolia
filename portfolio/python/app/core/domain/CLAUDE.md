# Calculation engine (`core/domain`)

**Purpose:** the only place portfolio maths is defined. Pure functions; no DB, no network, no FastAPI. Every number the app shows about positions, value history, returns or risk comes from here.

**State (2026-10-28):** ✅ in production use. Golden tests in `tests/unit/test_domain_engine.py`; an independent replay of the demo data (real Yahoo prices, splits, dividends) matched `daily_series` to the cent on every day and XIRR to 3 decimals. The characterisation snapshots were re-run and did not change. Every open position on a broker securities statement matches the share count and cost basis from that broker's trade confirmations, to the cent.

## Modules
| File | What | Key rules |
|---|---|---|
| `positions.py` | `to_trades`, `split_factor`, `Lots`, `compute_position`, `day_change`, `OversellError` | Only COMPLETED (or status-less) transactions. Order: date, buys and transfer-ins before sells and transfer-outs, id. Trades that move shares are converted to **today's share units** (qty × later split ratios, price ÷ same) because Yahoo closes are split-adjusted back in time. FIFO lots; cost = `total_amount` (fees+taxes in). A transfer in opens a lot at that cost. A sell or transfer out realises `total_amount + taxes − FIFO cost` (`realized_proceeds`): realized P&L is **before** tax withheld at sale (Trade Republic deducts German capital gains tax from the proceeds), net of fees. Reverse splits are just ratios below 1 (Beyond Meat 1:30 on 2026-08-14 = 0.0333). Oversell raises. |
| `fx.py` | `canonical_currency`, `rate_on`, `convert_series`, `convert_closes`, `convert_amount`, `convert_trades`, `MissingFxError` | `GBp`/`GBX` → GBP ÷100, `ILA` → ILS ÷100, once. Closes multiply by portfolio-per-1-quote, forward-filled; no rate on or before a day raises (subclass of `MissingPriceError`). Cash converts only when its currency differs. Golden tests: `tests/unit/test_fx.py`. |
| `valuation.py` | `daily_series(trades, closes, end, symbols)`, `daily_series_by_asset` (the same run plus one frame per asset: value, inflow, outflow, quantity, price, summing to the portfolio's), `trading_days`, `MissingPriceError`, `STALE_PRICE_DAYS` | Calendar = trading days present in the price data, from first trade to `end`. Weekend trades count on the next trading day. Prices forward-filled. A close older than 5 sessions is still used and that day sets `stale_price` plus `stale_symbols`. A held asset with **no** price raises (never valued at cost). Columns: value, cost_basis (FIFO, fees), net_invested (cum. inflow−outflow), inflow (buys and transfer-ins), outflow (sale and transfer-out cash received, i.e. after tax, + dividends), realized_pnl (before tax), dividends, stale_price, stale_symbols. Callers pass closes and cash already in the portfolio currency. |
| `benchmark.py` | `shadow_series(series, closes, start)` | The portfolio's own daily inflows buy benchmark units at the **previous** close, outflows sell at the day's close (the timing `compute_daily_returns` assumes), so the shadow's TWR is exactly the benchmark's price return; only MWR/profit differ. A later period opens with the portfolio's value before it. Withdrawals beyond the shadow's value → `shortfall`. Needs a total-return series (accumulating ETF / TR index). No price before the period → `MissingPriceError`. Golden tests: `tests/unit/test_benchmark_shadow.py`. |
| `returns.py` | `compute_daily_returns`, `twr_pct`, `annualize_pct`, `deannualize_pct`, `xirr_pct`, `volatility_pct`, `sharpe_ratio`, `max_drawdown_pct`, `value_at_risk_pct`, `split_period`, `period_summary`, `RISK_FREE_RATE`, `TRADING_DAYS_PER_YEAR` | Daily return r = (V_t + out_t)/(V_{t−1} + in_t) − 1 (buys at start of day, outflows at end). Percent units. Annualise only for ≥360 days. XIRR via pyxirr with the opening value as a flow the day before the period. Drawdown counts a fall from the period start. VaR = historical one-day quantile. One risk-free rate (3%). |
| `insight.py` | `contributions`, `calendar_returns`, `benchmark_returns`, `drawdowns`, `timing_effect`, `currency_effect(s)` | What drove a period. Contribution: each asset's daily (V_i + out_i − V_i,prev − in_i) over the portfolio's denominator, weighted by the growth before that day, so holdings sum **exactly** to the period's TWR (and profits to its profit), sold holdings included. Calendar returns compound daily returns per month/year; `partial` when the window does not cover the whole month/year. Benchmark returns are close-to-close on the portfolio's days (last close carried). Drawdowns: underwater curve of the compounded returns (period start counts as a peak, as `max_drawdown_pct`), deepest 5 episodes with peak, trough, recovery dates and calendar days. Timing effect = actual profit − profit of the same flows at the steady daily rate (1 + TWR)^(1/sessions) − 1; 0 without flows. Currency effect per foreign-quoted asset: Σ q_{t−1} · P_t · (1 − X_{t−1}/X_t), X = portfolio currency per unit of quote (converted ÷ local close); equals the profit when the local price is flat. Golden tests: `tests/unit/test_performance_insight.py`. |
| `planner.py` | `buy_only_split`, `detect_savings_plans`, `project_goal`, `with_annual_mean`, `monthly_returns` | Buy-only split = water-filling: level L with Σ max(0, t_i·L − c_i) = amount (targets normalised over targeted holdings; untargeted holdings get nothing and are left out), buys below `min_amount` dropped and the rest re-split. Savings plans: ≥3 purchases of a holding on a weekly / two-weekly / monthly / quarterly rhythm (median of the last 12 gaps), fee-free purchases preferred when there are ≥3, latest run with gaps ≤ 2× the rhythm's upper bound (one skipped execution), ≥60 % of its gaps in rhythm; amount = median of the last three; active within 1.5 rhythms + 4 days. Goal: block bootstrap (12-month blocks, circular) of monthly returns, contribution at the start of each month, 2,000 paths, seed 0; per path V0·G + C·A, so the monthly amount reaching the goal on p % of paths is the p-th percentile of (goal − V0·G) ÷ A. `with_annual_mean` shifts the history to an assumed annual mean and keeps its swings. Golden tests: `tests/unit/test_planner.py`. |
| `alerts.py` | `check_alerts`, `PRICE_HIGH`, `PRICE_LOW`, `PERCENT_CHANGE` | Watchlist thresholds: high at price ≥, low at ≤, percent when \|change since added\| ≥ threshold. Whether it notifies is the caller's decision (`WatchlistService`). Tests: `tests/unit/test_watchlist_alerts.py`. |
| `market_calendar.py` | `market_status`, `session`, `holidays`, `early_closes`, `is_trading_day` | NYSE: 9:30–16:00 New York time on weekdays; full holidays by rule (Good Friday from Easter, Juneteenth from 2022, Saturday→Friday and Sunday→Monday, but a Saturday New Year is not observed); 13:00 closes on the day after Thanksgiving and on 3 July and 24 December when they fall Monday–Thursday. Tests: `tests/unit/test_market_calendar.py`. |

`period_summary(series, start)` → start/end date and value, deposits, withdrawals, net_contributions, profit (= end − start − net), twr_pct, twr_annualized_pct, mwr_pct (period), mwr_annualized_pct (XIRR), volatility_pct, sharpe_ratio, max_drawdown_pct, best_day, worst_day.

## Who calls it
- `modules/analytics` `PortfolioCalculationService.get_portfolio_breakdown` (memoised per request: series, per-asset frames, foreign quote currencies and their rate series) → `get_portfolio_series` and `get_performance_insight` (`/portfolios/calculations/portfolio/{id}/insight`). `get_portfolio_series` → `/portfolios/calculations/.../performance`, `/performance/series`, `/multi-period`, `/benchmark` (+ `shadow_series`), analytics `/performance/history`, `/risk`, `/advance-risk` (via `get_portfolio_history`).
- `modules/analytics` `PortfolioAnalyticsService.engine_metrics` → `period_summary` + `value_at_risk_pct` for analytics `/summary`, `/users/dashboard` and the worker's performance snapshots. `risk.py` uses `RISK_FREE_RATE` and `value_at_risk_pct`.
- `modules/portfolios` `PortfolioService.recalculate_asset_state` → `compute_position` (cached `PortfolioAsset`), `_holding_rows` → `day_change`. The previous close is the last session before the current one (`market_data/sessions.py`), in the bar's timezone.
- `core/services/watchlist_service.py` → `check_alerts`. `transaction_pdf_export_service.py` → `convert_amount`.
- Prices: `MarketDataService.get_daily_history` (split-adjusted, not dividend-adjusted closes + split/dividend events; Redis 6h). FX: `get_fx_rates` reads `{QUOTE}{PORTFOLIO}=X` through that same cache (inverse pair if the direct one is missing). `load_rates` (`core/services/fx.py`) fetches; this package only multiplies.

## Rules for changes
- Add a golden test with a hand calculation **first**; keep `test_calculation_snapshots.py` green (regenerate only for intended changes, explained in the commit).
- Never re-implement a metric elsewhere (services, routers, frontend). Extend this package.
- Dividends are income only via DIVIDEND transactions (prices are not dividend-adjusted). SPLIT rows are ignored; splits come from market data. Transfer in/out open and close lots.
